## 背景与目标

后端已经具备文章和标签能力，需要一个可直接使用的网页界面，让访客能够阅读内容，让博客作者能够完成文章编辑。

本次改动交付博客的前端最小形态：文章列表、文章详情和文章编辑器形成完整的浏览与写作流程。

## 使用者

- 访客：浏览文章列表并阅读文章正文。
- 博客作者：新建和编辑文章。

当前版本尚未接入身份认证，因此作者入口只是功能入口，不代表已经具备安全的权限隔离。

## 产品形态

### 文章列表

- 展示文章标题、摘要、状态、标签和时间等主要信息。
- 支持分页浏览。
- 支持按标签筛选文章。
- 点击文章后进入对应详情页。

### 文章详情

- 展示文章的完整信息。
- 将 Markdown 正文渲染成适合阅读的页面内容。
- 提供进入当前文章编辑页的入口。

### 文章编辑器

- 新建和编辑共用同一个编辑体验。
- 可以编辑标题、slug、摘要、状态、标签和 Markdown 正文。
- 支持选择已有标签或输入新标签。
- 保存成功后进入文章详情页。

### 通用体验

- 页面包含统一的导航、主体区域和页脚。
- 加载、请求失败和不存在的页面都有明确反馈。
- 开发环境中的前端请求可以直接访问后端 API。

## 本次范围

- 文章列表、文章详情、文章编辑和 404 页面。
- Markdown 编辑与渲染。
- 分页、标签筛选及文章相关 API 对接。
- 前端路由、请求状态和通用反馈组件。

## 非目标

- 登录和权限控制。
- 独立的后台管理系统。
- 评论、搜索、归档和媒体库。
- 自动化测试和生产部署。
- 完整落实最终 UI 视觉规范。

## 验收标准

- 访客可以从首页进入一篇文章并正确阅读 Markdown 内容。
- 文章列表能够分页并按标签筛选。
- 作者可以通过表单创建一篇文章。
- 作者可以加载并修改已有文章。
- 保存后的数据来自后端，刷新页面后不会丢失。
- 接口请求期间显示加载状态，失败时显示可理解的错误。
- 未匹配的地址显示 404 页面。
