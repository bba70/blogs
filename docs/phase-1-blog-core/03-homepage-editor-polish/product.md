# 03 首页与编辑器体验优化 — 产品定义

> Phase: 1（博客核心）  
> Status: 已完成

## 背景与目标

现有首页已经具备文章浏览能力，但进入页面后直接展示文章列表，缺少能够表达作者身份和博客定位的第一屏。文章编辑器也存在异步加载时正文初始化不稳定、工具入口不够清晰的问题。

本次改动增强首页的个人博客形态，并让新建、编辑文章时的 Markdown 写作体验更加稳定。

## 使用者

- 访客：进入博客后快速了解作者和内容定位，再继续浏览文章。
- 博客作者：可靠地加载已有文章，并使用完整的 Markdown 工具栏编辑正文。

## 产品形态

### 首页首屏

- 首屏展示博客品牌、作者介绍、内容定位和最新文章入口。
- 提供 GitHub、邮箱和 RSS 的视觉入口，为后续配置真实地址预留位置。
- 提供向下滚动入口，将访客引导至文章区域。

### 导航

- 导航明确区分“首页”和“博客”。
- 品牌区域使用统一头像和博客名称。
- 搜索入口采用更轻量的胶囊式交互。
- 移除导航中的公开“新建文章”按钮，避免访客界面暴露作者操作入口。

### 文章区域

- 文章内容在首屏之后继续展示，保留精选文章、筛选、分页和作者侧栏。
- 初次加载和加载失败时保留完整页面结构，只在文章区域显示对应反馈。

### 编辑器

- 编辑已有文章时，正文必须在数据加载完成后正确出现。
- 在新建和编辑模式间切换时，不沿用上一份文章内容。
- 编辑器显示常用 Markdown 顶栏，并保持与博客整体视觉风格一致。
- 桌面端和移动端均提供足够的正文编辑空间。

## 本次范围

- 首页 Hero、导航和文章区域状态布局。
- 品牌、社交入口、滚动引导和响应式样式。
- 编辑文章时的异步数据回填和编辑器生命周期处理。
- Milkdown 顶栏、主题引入及局部样式定制。

## 非目标

- 配置真实的 GitHub、邮箱和 RSS 地址。
- 实现专题、归档和关于页面。
- 改造后端接口或数据结构。
- 实现登录后的作者工作台入口。

## 验收标准

- 首页首屏在桌面端和移动端均正常排版，并能跳转到文章区域。
- 首页和博客导航状态能够正确区分。
- 请求文章期间仍能看到首页框架，加载或错误反馈出现在文章区域。
- 新建文章时编辑器为空，编辑文章时显示对应文章正文。
- 在不同文章及新建/编辑模式间切换时不会串用正文。
- Milkdown 顶栏可见，编辑区域在移动端不会出现明显布局溢出。
- 前端生产构建和 ESLint 检查通过。
