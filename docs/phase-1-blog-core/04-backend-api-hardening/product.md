# 04 博客接口可靠性增强 — 产品定义

> Phase: 1（博客核心）  
> Status: 已完成

## 背景与目标

博客核心接口已经可以完成文章增删改查，但在公开访问、异常输入和文章状态变更等场景中仍缺少必要边界。例如文章列表默认可能暴露草稿、重复 slug 会返回不明确的服务器错误，部分无效内容只能依赖数据库拒绝。

本次改动完善文章接口的业务规则和错误反馈，使公开读取更安全、作者编辑更可靠，并减少异常请求对服务的影响。

## 使用者

- 访客：默认只看到已经发布的文章。
- 博客作者：创建和编辑文章时获得明确的校验、冲突及不存在提示。
- 运维与开发者：从服务日志中定位真实错误，同时避免内部细节暴露给客户端。

## 产品能力

### 公开文章范围

- 未指定状态时，文章列表只返回已发布文章。
- 管理场景可以通过 `status=all` 请求全部状态；正式认证完成后，该能力需要限制为管理员使用。

### 输入校验

- 标题和 slug 必填，并拒绝只包含空白的内容。
- 标题、slug 和摘要不得超过数据库允许的长度。
- 文章状态只接受 `draft` 或 `published`。
- 单次创建或更新请求体最大为 2 MB。

### 编辑与发布

- 编辑文章时可以修改 slug。
- slug 与其他文章冲突时返回明确的冲突响应。
- 文章首次发布时记录发布时间；取消发布后再次发布保留原发布时间。
- 每次实际更新都由数据库刷新 `updated_at`。

### 错误反馈

- 参数错误返回 400。
- 文章不存在返回 404。
- slug 冲突返回 409。
- 未预期错误只向客户端返回通用提示，真实原因记录在服务日志中。

## 本次范围

- 创建和更新文章的业务校验。
- 文章列表的默认状态规则。
- slug 更新及唯一约束冲突处理。
- 发布时间、更新时间和删除错误处理。
- 请求体限制、统一错误映射和 CORS 配置修正。

## 非目标

- 用户认证及管理员权限判断。
- 修改数据库结构。
- 评论、媒体和搜索接口。
- 完整事务化文章与标签写入。
- 新增前端页面或交互。

## 验收标准

- 不传 `status` 查询文章列表时不会返回草稿。
- 合法的创建、更新和删除请求保持原有接口行为。
- 空标题、空 slug、超长字段和非法状态返回 400。
- 创建或更新为重复 slug 时返回 409，而不是 500。
- 修改 slug 后能够通过新 slug 读取文章。
- 更新不存在或删除不存在的文章均返回 404。
- 超过 2 MB 的请求体被拒绝。
- 内部数据库错误不会直接出现在客户端响应中。
- 后端代码格式检查和 `go test ./...` 通过。
